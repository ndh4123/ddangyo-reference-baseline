# 땡겨요 홈페이지 레퍼런스 분석

분석 대상: `https://www.ddangyo.com/#2`  
분석 화면: Desktop 1440×900, Tablet 768×1024, Mobile 390×844  
분석 일자: 2026-08-30

## 전체 구조

레퍼런스는 일반적인 장문 문서가 아니라 고정 헤더 아래 화면 높이 단위로 전환되는 11개 섹션으로 구성된다. 실제 문서 높이는 한 화면에 고정되어 있고 내부 컨테이너가 세로로 이동하며 URL 해시가 `#0`부터 `#10`까지 변경된다.

1. Hero — 서비스 슬로건, CTA, 중앙 휴대폰, 주변 음식 오브젝트
2. Benefits — “왜 땡겨요?” 제목과 6개 혜택 카드
3. Question — 어두운 배경, 순차 등장하는 질문과 캐릭터
4. Fair fee & regulars — 2% 수수료와 사장님/고객 단골 혜택을 순환 노출
5. Shared culture — 전체 화면 사진 위 중앙 메시지
6. Review reward — 좌측 카피, 우측 리뷰 피드 휴대폰
7. Social review — 좌측 카피, 우측 그리드형 휴대폰과 장식 원
8. Recommendation — 휴대폰과 개인화 추천 카피
9. Local voucher — 결제 휴대폰과 서울사랑상품권 카피
10. Nationwide — 중앙 대형 제목, 지도형 그래픽
11. Closing & footer — 배달 장면 이미지 위 메시지, 하단 약관 푸터

## 레이아웃 특징

- Desktop 헤더 높이 68px, 섹션 높이 100vh, 기준 콘텐츠 폭 약 1055px(좌우 약 193px).
- 주요 기능 화면은 대체로 680~720px 너비의 2열 구성이며 텍스트 268~310px, 휴대폰 300~340px이다.
- Benefits 카드의 실측 크기는 약 226×236px이며 3열로 배치된다. 두 번째 행은 다음 흐름을 암시하듯 뷰포트 아래쪽에 일부만 보인다.
- 태블릿은 고정 헤더를 유지하면서 콘텐츠 폭을 줄이고 Benefits를 2열 일부 노출로 바꾼다.
- 모바일 헤더는 로고 48px 행과 CTA 48px 행의 2단 구조다. 화면 섹션은 100svh를 유지하고, Benefits는 가로 스크롤 카드 한 장과 다음 카드 일부를 노출한다.
- 마지막 섹션은 Desktop에서 약 744px의 비주얼과 156px 푸터, Mobile에서 약 558px의 비주얼과 나머지 세로 푸터로 나뉜다.

## 컬러

- 기본 배경: `#ffffff`
- 기본 제목: `#181818`
- 본문/보조 텍스트: 약 `#7d7d7d`, 밝은 본문은 `#a5a5a5`
- 핵심 포인트/CTA: 주황-적색 계열 약 `#ff4b1f`
- Question 섹션: 실측 `rgb(57, 61, 76)` (`#393d4c`)
- 푸터: 짙은 청회색 약 `#1f242b`
- 카드 외곽선: 아주 옅은 주황/회색, 강한 그림자 대신 낮은 대비의 확산 그림자 사용

## 타이포그래피

- 원본은 `NotoSans` 계열을 사용한다. 기준본은 외부 폰트 요청 없이 시스템 한국어 산세리프 스택을 사용한다.
- Desktop 메인/섹션 제목: 48~60px, 700~800, line-height 약 1.2.
- Desktop 보조 제목: 24px, line-height 약 1.6.
- 기능 화면 본문: 22~24px, line-height 1.6.
- 모바일 제목: 약 30~34px, 본문 16~18px. 줄바꿈을 원본과 유사한 위치에 고정한다.

## 이미지와 그래픽

- 레퍼런스의 로고, 캐릭터, 음식 사진, 휴대폰 캡처, 배달 사진은 고유 브랜드 자산이므로 기준본에 복제하지 않는다.
- 동일한 비율과 위치를 CSS 도형, 추상 음식 토큰, 자체 제작 휴대폰 와이어프레임, 색면 기반 사진 placeholder로 대체한다.
- 휴대폰은 약 0.47:1 비율, 30~44px radius, 옅은 외곽선/그림자를 갖는다.
- 풀 블리드 사진 섹션은 `cover`와 중앙 또는 우측 초점을 사용하고 반투명 어두운 오버레이를 겹친다.

## 주요 인터랙션과 애니메이션

- 휠/키보드/터치 스크롤 시 다음 화면으로 스냅되며 약 0.7~0.9초 동안 부드럽게 이동한다.
- 활성 섹션 진입 시 제목은 24~50px 아래에서 상승하고 opacity가 0→1로 변한다.
- 기능 섹션의 텍스트는 0.2초 지연, 본문은 0.4초 지연으로 약 0.5초 ease-out 전환된다.
- 휴대폰은 0.7~1초 ease-out으로 아래에서 올라오거나 좌우에서 진입한다.
- Question 섹션은 문장별 opacity가 순차 강조되고 캐릭터 위치가 좌상단/우하단으로 분리된다.
- 수수료 섹션은 상단 핵심 문구를 유지하면서 하단 사장님/고객 혜택 상태를 순환한다.
- `prefers-reduced-motion`에서는 자동 순환과 큰 이동을 끄고 즉시 표시해야 한다.

## Desktop / Tablet / Mobile 차이

- Desktop: 헤더 CTA 3개, Benefits 3열, 기능 섹션 2열, 60px 헤드라인.
- Tablet: 헤더 구조 유지, Benefits 2열 일부 노출, 기능 그래픽 폭 축소, 주변 오브젝트 수 감소.
- Mobile: 헤더 2단, Benefits 가로 스크롤, 기능 섹션은 카피 위/그래픽 아래 단일 열, 제목 32px 안팎.
- Mobile에서는 히어로의 중앙 앱 다운로드 버튼과 일부 장식물을 숨기고 휴대폰을 더 크게 보이게 한다.
- 모바일 가로 넘침은 Benefits 내부 가로 스크롤만 허용하며 문서 자체는 `overflow-x: hidden`으로 유지한다.

## 구현 시 주의사항

- 휠 잠금은 짧게 유지해 한 번의 휠 입력으로 두 섹션 이상 이동하지 않게 한다.
- 헤더는 섹션 배경에 따라 밝은/어두운 테마를 전환한다.
- 해시 직접 접근과 뒤로 가기를 지원한다.
- 외부 이미지와 원본 자산을 사용하지 않아 broken image/저작권 위험을 제거한다.
- 100vh 대신 모바일 주소창 변화에 강한 100svh를 우선 사용하고, 마지막 화면은 푸터 높이를 포함해 한 화면에 맞춘다.
